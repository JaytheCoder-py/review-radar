# Decision log

Every judgement call, and the alternative rejected. Add to this rather than silently
changing a threshold.

Format:

```
## D-NNN — <short title>
**Decision.** What was chosen.
**Why.** The reasoning.
**Rejected.** The alternative, and what it would have cost.
```

---

## D-001 — The event log is append-only

**Decision.** Extractions are only ever inserted. A corrected extraction is a new row
carrying `supersedes` pointing at the row it replaces. Nothing is updated or deleted.

**Why.** What the system *said* is itself a record. If a downstream consumer acted on
last night's extraction, rewriting it destroys the ability to audit that decision. Index
providers keep a recalculation policy for exactly this reason: a published number that
later changes is an event, not a correction to be applied silently.

**Rejected.** Upsert on `(accession, field)`, keeping only the current best answer.
Simpler to query and half the storage, but it makes "why did we act on this?" permanently
unanswerable, and it hides the extraction instability that the scoreboard exists to
measure.

## D-002 — Parsing is separated from fetching

**Decision.** `EdgarClient.parse_daily_index` and `EdgarClient.parse_submission` are pure
static functions over text. All network I/O lives in `daily_index` and `fetch`.

**Why.** It makes the entire parsing surface testable against committed fixtures with no
network, which is the difference between a test suite that runs in CI and one that
doesn't. It also means a pathological filing can be reproduced by committing the bytes.

**Rejected.** Methods that fetch and parse together. Marginally less code, and untestable
without either a live SEC connection or an HTTP mocking layer that would itself need
maintaining.

## D-003 — Item numbers are recovered from header description strings, not parsed from the body

**Decision.** The baseline classifier maps the standardised `ITEM INFORMATION:` strings in
the SGML header to item numbers via a lookup table built from the SEC's own item list.

**Why.** This was established by probe, not assumption — see
`memos/W2_what_the_8k_header_actually_contains.md`. The header carries the item
*description*, never the number. The number does appear in the document body, but the body
is HTML with tags and entities interleaved between "Item" and "5.02", so recovering it
requires normalising the HTML first and is unreliable across filer agents.

The description strings are generated by EDGAR from a fixed vocabulary, so a lookup table
is exact rather than heuristic. Unrecognised strings are surfaced loudly rather than
silently dropped, because a new or changed SEC label must not degrade classification
quietly.

**Rejected.** Regex over the normalised body text. Filer agents differ in markup, several
use images for headings, and any miss looks identical to "this filing had no such item".

## D-004 — The baseline eliminates on the whole item set, never on a single item

**Decision.** A filing is classified `NO_INDEX_ACTION` only when *every* item it carries is
in `NO_CONSEQUENCE_ITEMS`. The presence of one harmless item never eliminates a filing.

**Why.** Companies routinely file 2.02 (results) and 2.01 (completed acquisition) in one
8-K. Eliminating on the presence of a harmless item drops the event sitting next to it,
and the failure is invisible — the filing simply never appears in the queue.

**Rejected.** Eliminating on the primary item. Cheaper, and wrong on precisely the filings
that matter most.

## D-005 — A ratio is a `Fraction`, never a float

**Decision.** `Ratio = Fraction`. Nothing constructs one from a float.

**Why.** `Fraction(0.1)` is the exact binary double, not one tenth. A 1-for-3 reverse split
held as a float does not invert cleanly, and the residue lands in a divisor — the numbers
this system exists to protect.

**Rejected.** `Decimal`. Exact for the decimal fractions but not for thirds, and ratios in
corporate actions are natural quotients ("three for one", "one for eight"), not decimals.

## D-006 — The model client is optional at install time

**Decision.** The real Vertex client lives behind the `vertex` extra and is imported
lazily. `OfflineLlm` — deterministic, keyed on a hash of the prompt — is the default, and
the entire test suite plus CI runs on it.

**Why.** A clone with no cloud account must run the full pipeline end to end. CI must cost
nothing and need no credentials. Only the eval job, run deliberately, spends money.

**Rejected.** A single client with a mock injected in tests. Equivalent for testing, but it
puts an unconditional cloud dependency in the install path of a repository whose point is
that it runs anywhere.
